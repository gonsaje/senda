# Senda

A native iPhone training notebook. Browse a week, open a day, and enter individual sets. The app saves locally and supports optional backups to a private iCloud Drive folder.

## Run

1. Open **Senda.xcodeproj** in Xcode 16.4 or later with an iOS 17+ simulator.
2. Open **Profile → Settings → Explore sample journal** to try 12 weeks of sample workouts. **Exit demo** returns to your journal and discards demo edits. The **Senda Sample** scheme opens the same sample workouts directly.
3. Run **Senda** for a real journal with automatic local persistence and recovery. Physical-device builds need your development team and signing configuration.

The project has no third-party dependencies or generation step.

## App sections

The floating dock has **Train**, **Trends**, **Workouts**, and **Profile**. At accessibility sizes, the four labels grow in a two-column layout. Press and hold a tab for the system’s large label-and-symbol preview. The active tab has a tinted background, a bold label and a selected accessibility trait. In Workouts, an underline marks the active section. Tap **Train** to return to today in your preferred layout from any screen in the main navigation. Tap another selected tab again to return to its landing view. Switching sections keeps unfinished set entries recoverable.

**Workout plans** live beneath each exercise’s heading. Set a working-set target and rep range for that workout; targets stay separate from recorded sets. New exercise entries reuse the plan from the nearest earlier workout containing that exercise. Reusing a chosen workout also copies its plans only for newly added exercises. Past workouts keep their own plan, and removing the latest plan prevents an older target being silently revived.

**Set type** has its own control and defaults to Working set. Choose Working set, Warm-up or Drop set; choices save immediately. Older Regular annotations display as Working without rewriting stored history. A Drop set is one entry with a starting weight/reps stage and numbered drops. **Add drop** creates the next editable stage; every valid update saves automatically. The entry counts once in day/week/Trends totals while history retains every stage. Warm-ups and Drop sets do not count toward the Working target, and Drop workouts receive manual load-review guidance. Repeating a Drop entry copies every stage with fresh identities and clears effort; delete/Undo acts on the complete entry, and individual stages can be removed. Choosing another type splits stages into separate sets while retaining their values. Optional **Reps left** lives in row actions and appears inline when set. [UX audit](docs/design/2026-11-09-ui-ux-audit.md).

**Next workout** feedback uses journal-recorded working sets and saved plan snapshots. It can suggest repeating a load, building reps within the range, or reviewing a small load increase after two consecutive comparable workouts meet the top rep target with at least 2 reps left on every working set. This is a conservative, visible app rule; it does not choose an increase or change a weight. Missing effort/type, incomplete/extra sets, mixed loads, changed plans or below-range reps produce specific review messages. [Plan and guidance details](docs/implementation/2026-11-09-training-plans.md).

**Trends** starts with an empty Strength progress tracking list. Choose exercises individually, add the exercises from a saved, starter or logged workout, or use Add all. Done saves the list in your notebook. Select a tracked exercise to see its chart. Tap or drag across the chart to inspect a recorded day’s top set and compare it with the previous day in the range. Diamonds mark new load or rep records. View history opens that exercise’s recorded days. Weighted sets plot top-set load; body-weight-only windows plot best reps, and mixed added-weight windows label the added load. A single day is one point; empty windows have no chart. Choose 1 month, 3 months, 6 months, or 1 year through today. The default is 3 months. The overview shows training days, recorded sets, exercises trained, and weekly training-day bars for the selected range. History and Records sit beside the title, adapting to narrow screens and Larger Text. Records opens a separate screen with all-time personal records and the Big 3 total. This week compares only the same elapsed weekdays last week. Top-set comparison rows show the latest two recorded days: rep changes at the same load, load changes at the same reps, matched sets or neutral side-by-side changes. Milestones mark heavier weight, or more reps at the same weight, against all earlier history; first observations and ties are not new records. Comparisons and Milestones appear before weekly activity. Each comparison keeps its dated source sets, using a single line where readable and stacking with Larger Text. Rows and all-time records open read-only exercise history without moving the current workout. Regenerate the focused visual fixtures with `swift run senda-preview --trends-only /absolute/output/directory`. [Trends details](docs/implementation/2026-11-09-trends-overview.md).

**Trends** remembers whether you last opened **Training** or **Body**. **Body** opens with measurements and logging, followed by today’s activity. Use **Log a reading** to save dated body weight, waist circumference, or body fat readings. Choose a metric to see its recent chart and complete history, and tap a manual entry to edit or delete it. **Connect Apple Health** reads the measurements you allow, daily steps, and active calories. **Add activity** saves manually entered amounts to Health. **Apple Health → Sync measurements to Health** shares existing and future manual readings of the types you authorize, including edits and deletions. The history shows each source. Manual measurements are stored on this iPhone and included when you choose **Save full backup**. Automatic iCloud backups contain workouts and profile details. Restoring an older or automatic backup preserves the manual readings on your device. Imported readings come from Apple Health and are held in memory while viewing the history.

**Profile** shows active and completed lift goals. Set a target weight and reps for an exercise. A goal is complete once a saved set reaches both targets. Goal progress updates as you record or correct sets. The **Settings** gear opens **Edit profile**, **Weight units**, and **Workout recovery**. The name is optional and saved on this device. Cancel and Done remain visible while editing; the keyboard’s Done action uses the same save and validation. Weight units opens only the lb/kg choices, with changes saved immediately. All logged exercise PRs and the Big 3 breakdown live in Trends → Records. It does not create an account or automatically sync. Email is no longer requested or shown; previously saved profile data remains compatible. The total adds the heaviest logged bench, deadlift and squat sets; reps break weight ties. A total appears only when all three lifts have records. This is a sum of observed sets, not an estimated one-rep max or competition result. Tap a PR to inspect its original set in read-only history. Corrections, deletion and Undo update progress from the journal. Default units affect progress and new days, preserving existing day units and canonical weights.

Profile details, lift goals, and weekly set targets use a separate versioned local file. An unreadable profile stays untouched and does not prevent logging. There is no account authentication or synchronization.

**Exercise history** is available from Trends or the chart button beside the current exercise. Choose an exercise and a chart range. Exercise history shares the range with Trends. Recorded days lists all saved dates independently of that chart window, including older and deliberately future-dated entries. Daily points show actual top recorded sets; weighted exercises use load then reps, bodyweight-only periods use best reps, and mixed bodyweight/loaded periods show added load. Weekly training counts include inactive weeks. Dates use the saved training-day keys, so changing timezone does not move linked history. Newest-first days open the exact saved sets inside Exercise history, preserving the current workout; **Return to workout** closes into the same selected day/exercise. **Edit this workout** explicitly opens the saved day for corrections. A persistent return control restores the original workout/exercise or week while retaining the historical edits. Drafts and unfinished correction text are excluded from observations, while corrections/deletion/Undo and restore update them from performed history. [Progress details](docs/implementation/2026-11-09-exercise-progress.md).

**Workout recovery** opens from the Settings gear in Profile. **Choose backup folder** enables automatic backups to a private folder in iCloud Drive. Senda saves a separate dated backup when the notebook changes, up to once every 24 hours while the app is open. **Back up now** saves an extra copy at any time. Turning off automatic backups leaves existing copies in the folder. Apple handles uploading to the user’s iCloud account. **Save full backup** exports a Senda JSON file containing the complete notebook, workout plans, set type/effort annotations, custom exercises, recorded identities, dates, exercise order, units, unfinished edits, local profile details, lift goals, weekly set targets, and manual body measurements. **Export recorded sets (CSV)** produces a readable spreadsheet with exact lb/kg weights and recorded set IDs; CSV cannot restore the notebook. For a manual export, choose where to save each copy in Files. Senda does not encrypt exported files.

**Choose backup file** validates a Senda JSON file (up to 50 MiB), shows its contents and asks for confirmation before replacing the current notebook and local details. It does not merge. A pre-restore copy is retained on this device. Open it with **Review pre-restore copy** or export it with **Save pre-restore copy**. Interrupted or failed file replacements recover the original journal, profile, and manual readings before normal use. If the notebook cannot open, recovery also offers an unchanged original-file export and validated restore. When original files are damaged, the protected raw-file copy is exportable for recovery and is clearly distinguished from a restorable full backup. [Implementation and verification](docs/implementation/2026-11-09-backup-profile.md).

On opening **Workouts**, you can browse workouts or switch to **Exercises** or **Learn**. Each exercise appears under one main category. Muscle searches and workout filters can find it through any of its muscle tags, including supporting muscles. Custom exercises can have multiple muscle tags. Open **Learn** for 20 offline form guides and muscle guides for strength exercises. Maps distinguish primary movers, assisting muscles and loaded stabilizers. Mobility and conditioning entries have searchable muscle tags and contribute no strength sets. Fifteen variations include inspected, licensed start/end illustrations; tap a position to enlarge it. Exercise listings include visual thumbnails and named primary muscles. Search supports exercise names, muscle groups and equipment, with Clear search and an actionable empty state. Opening a guide slides forward to its title. Back reverses the slide and restores the search and scroll position. Guide headings follow the notebook scale, and the enlarged illustration header adapts to Larger Text. Broad exercise names specify the variation covered. Custom exercises remain searchable and clearly show when a guide has not been added. Coaching references and illustration credits open only on tap. [Form sources](docs/implementation/2026-11-08-form-sources.md), [anatomy notes](docs/implementation/2026-11-09-learn-anatomy.md), [artwork credits and coverage](docs/implementation/2026-11-09-learn-artwork.md).

Save a gym and its available equipment in **Filters**. Tap a saved setup to switch locations or **Browse all** to search the whole library. Setups stay on this device. When a named exercise falls outside your filters, Senda explains why and shows a related movement when one fits.

In **Workouts → Exercises → My exercises**, turn on **Needs details** to find custom movements missing a gym type or equipment list. Tap a movement to add its details. When you mark a custom movement **No equipment**, you can record reps with the weight blank.

## Notebook flow

- **Week → Day → Exercise.** Week shows the date range, workout count, and set count. The seven day rows show recorded lifts and set totals. Empty days show **Add workout**. Open an empty day to **Add exercise** or **Choose a template**. Prepared days show their planned exercise count before the first set is logged. A day with unfinished input offers **Continue workout**. Swipe up for the next week or down for the previous week. If the week scrolls, swipe on its date header. The arrows change weeks. Tap **Train** to return to today. Choose **Week** or **Month** beside the Senda wordmark. Week is the initial layout, and Senda remembers your choice on this device. In Month, swipe horizontally across the calendar or use its arrows to change months. The grid stays six rows tall. Tap a date to see its workout beneath the calendar. A filled dot marks logged sets and a hollow dot marks a prepared workout. Open the workout or add an exercise from the selected date. Returning from the workout keeps that date selected. Tap a day in Week to open that day's workout. The first successful set save displays **First set saved**.
- **Week → Muscles** shows which muscles you trained through today. Each working set or group of drop sets counts once toward every primary and supporting muscle it trained, and once in the workout total. Tap a muscle to see its lifts and training days. Weekly set targets use primary sets. Edit the selected muscle’s target here or manage all targets in **Profile**.
- Open **Workouts** in the dock or **Choose a template** on an empty workout. **Starters** leads with Push, Pull, and Legs. **My templates** holds your saved routines. You can create, edit or delete a personal template. To customize a built-in starter, open it and choose **Save a copy**. Deleting a template keeps workouts already logged. **Recent** lets you inspect an earlier workout’s recorded sets before reusing its exercises. Each preview names the destination date. Applying a workout returns to Train on the date shown. An open workout supplies its date, and Week defaults to today. Applying a workout adds missing exercises and their targets with blank rows. Existing sets and drafts stay in place. From an active workout, choose **Edit**, then **Workout actions → Save as template** to save its exercise order and targets. Full backups include your saved templates.
- Swipe the exercise tabs to browse the workout. Tap a name to switch lifts. The underlined tab shows which lift you’re logging, and **＋** opens the exercise chooser. Tap **Edit** to open **All exercises**. From there you can reorder exercises, create a superset, or use an exercise’s options to hide its tab or delete it from the workout. Tap a hidden exercise to reopen its saved sets or unfinished input. A grouped Drop entry counts as one set.
- To pair two lifts, tap **Create superset**, choose them in the order you’ll do them, then set the rounds and rest. Logging the first working set for A1 starts round one. If you already logged an A1 set before pairing, **Start superset** lets you choose whether to count it. Use the pair’s **Edit** menu to adjust remaining rounds and future rest breaks or unpair the lifts. Hiding either member hides both tabs and keeps the round and timer. **Undo** restores hidden tabs or an unpaired superset.
- **＋ Add** opens a search field inside the workout, with recent exercises first. Tap a result to open its sets. **Browse all exercises** carries the search into the full catalogue. Search, muscle-group and equipment filters apply together; the compact **Filters** disclosure shows active restrictions, and **Clear filters** keeps the search text. Flat rows show **Added** when already in the day. Normal selection adds one exercise; **Select several** keeps an ordered selection for one atomic **Add N exercises** action. Failed selection remains visible and retryable; changing intent or Cancel prevents an old failed add from appearing later. **Create exercise** accepts a name, muscle group, and main equipment. Under **Gym & equipment**, choose the gym types where you can do the exercise and the gear it requires. Choose **No equipment** for equipment-free movements. In **Workouts → Exercises**, use **New custom exercise** to create a movement. Open an exercise and tap **Add to workout** to choose a date. The sheet starts on the open workout’s date or today. If the exercise is already on that day, **Open in workout** takes you to its existing sets. Open a custom exercise you own to edit its name, muscle group, equipment or gym details. Deleting it removes it from future exercise choices. Past workouts keep the exercise name, sets, weights and reps, including after a backup restore. Reusing a workout skips removed exercises. Adding a new exercise with the same name starts a separate history. Built-in exercises and guides are read-only. Existing unclassified custom exercises remain searchable under Full body / Other.
- Each set has one weight value and reps. The **lb/kg button below the tabs** switches the day's display unit with one tap and preserves the exact recorded weights. **Last time** shows the preceding workout’s top set for this lift. Tap **History** to read dated saved sets and return to this workout. **PR** shows the personal record; **Last set** beside prefill uses the immediately preceding recorded set. PR ranks performed weight first, then reps. Tap a reference to inspect its source day read-only.
- A newly added exercise starts with a blank row. **New set** reuses an entirely empty final row, or adds another blank row, and focuses Weight or bodyweight Reps. A blank row’s actions menu offers **Use last values** when there’s an earlier set. Tapping it saves a new editable set with those values immediately.
- Tap a value to edit. **Reps →** moves from Weight to Reps within the row. On a complete final row, **Next set** opens a blank working set using the current input method. Incomplete input or a save error keeps that continuation unavailable. The weight and reps editor takes the place of the app dock. Every valid update saves immediately, including dial, plate and step controls. **Done** closes the editor and brings the dock back. A weighted set needs a weight and 1–999 reps; bodyweight needs reps alone. Explicit zero weight is allowed.
- A complete new row counts immediately while editing. Partial input is saved without adding an invalid observation to history. If an existing set temporarily has an incomplete value, its last valid values and identity stay in history. Simple field guidance explains what needs a value; **Restore saved values** restores the last valid set. Valid corrections update that same set automatically. Explicit deletion remains separate.
- There is no recording step, recorded/not-recorded row label or completion checkbox. A save failure retains current input and offers Retry. Retry preserves set identity and saves once. An abruptly interrupted edit reopens with its saved input.
- The weight editor opens on **Dial**. Switch to **Plates** to add or subtract one plate or one per side. **Plate math** splits a total across both sides of your chosen bar. It previews the plate sizes and offers nearby totals when needed. Tap **Use** to apply the load to the set. Pound plates range from 2.5 to 55 lb and kilogram plates from 1.25 to 25 kg. Plate changes start from the set’s current weight, or zero for a blank weight. **Undo** reverses the last plate change on that set, including both plates when you chose one per side. Changing the selected size or count keeps Undo tied to the original change. Tap its large value to type; the ruler steps aside for the keyboard. The keyboard-dismiss button returns to the selected weight control. Reps open directly for typing. The editor always labels Weight with the current unit or Reps. During editing, headings compact and Last/PR become an expandable reference. At accessibility text sizes, row values stack and grow, and typing plus large steppers replace the visual ruler.
- **Repeat last set** copies the immediately preceding complete entry and counts it immediately. For a Drop entry it repeats every stage under a fresh group ID, preserving exact values and clearing effort. **Undo** removes that copy; Undo after deleting an entry restores all original rows and identities. New edits or navigation clear the older undo action.
- Each entry has a three-dot menu for optional effort and deletion. Drop stages have their own effort/removal menus. Swipe left to reveal a red X; swipe farther and release to delete the whole entry. Vertical scrolling and cancelled gestures never delete. Failed saves remain retryable. **Undo** restores the entry in its original position.
- Open the exercise menu and choose **Hide an exercise**. This retains its rows and history; every recorded or meaningfully unfinished hidden exercise remains reachable in **All**. The week's totals still reflect actual performed sets.
- To reuse a day, open **Recent** under **Workouts** or **Choose a template**. Preview a day, then choose **Use this workout**. Senda appends missing exercises in source order with blank rows, preserving destination sets and drafts. It never copies performed records, weights or reps. Repeating the action is harmless.

## Tests

```sh
bash scripts/test.sh
swift run senda-sample
# Full Xcode and an installed iOS runtime:
bash scripts/test-ios.sh
SENDA_SIMULATOR_NAME='iPhone 13 mini' bash scripts/test-ios.sh
```

Unit tests use Swift Testing and work with standalone Mac Command Line Tools. Restricted environments can pass writable cache locations and `--disable-sandbox`. The iPhone script creates and removes only its own temporary simulator; `SENDA_SIMULATOR_ID` can use an existing simulator. Results are in ignored `TestResults/`, or `SENDA_TEST_RESULTS`. Both Xcode schemes include the interaction tests for ⌘U.

The GitHub **iPhone validation** workflow runs unit tests and interactions on iPhone 16 and iPhone 13 mini using Xcode 16.4. Debug UI tests use UUID-isolated journals. Result bundles are retained for seven days. The workflow does not deploy a service.

Coverage includes ordered batch/set identities, duplicate-action protection, automatic row boundaries, incomplete recovery, bodyweight requirements, day isolation and summaries, Last/PR projections, date/DST arithmetic, exact lb/kg conversion and unchanged-input echoes, repeat/delete undo, invalid workspace data, custom exercise classification, legacy editor recovery, migrations and failed atomic writes. iPhone flows cover navigation, entry, units, rapid typing, finger dial, recovery, source-day editing, grouped/custom picking, undo and large text.

## Architecture and data

| Module | Responsibility |
| --- | --- |
| `SendaDomain` | Journal commands and receipts, individual set operations, validated day/workspace values, classification and conversion |
| `SendaPersistence` | Main-actor snapshot repository; memory and versioned atomic JSON adapters |
| `SendaLogger` | Weekly application model, candidate transactions, projections and legacy recovery review; original logger retained for compatibility |
| `SendaNotebook` | Native week/day/picker views, set rows, banners, numeric input and recovered-entry UI |
| `App` | Real/sample composition, lifecycle finishing and local-file opening |

The real file stays at Application Support `Senda/journal-v1.json`. Format 7 stores the journal, custom library and weekly workspace atomically, including explicit Drop groups and grouped Undo. Saved workout templates use journal format 8 and backup format 7. Notebooks with gym or equipment details on custom exercises use journal format 9 and backup format 8. Notebooks with archived custom exercises use journal format 10 and backup format 9. Earlier journal formats still open. Full backups with manual measurements use format 11. Managed program schedules, hidden superset tabs, and their new undo actions use journal and backup format 12. Custom exercises with muscle tags or the Neck category use journal and backup format 13 and shared program format 3. Senda also reads older journals, backups and program files. CSV includes group and stage columns.

Performed IDs, original dates and consumed action receipts are preserved. Day membership is explicit, so time-zone changes do not relocate saved sets. Undated legacy unfinished sessions move to the migration day's workspace without being counted. Removed-tab sessions remain recoverable. A legacy open group editor or pending recorded correction gets a one-time Done/Cancel review before weekly migration. Input in that review is also recoverable. Old unfinished batches are never automatically recorded during migration.

Weights are integer hundredths of a pound. Kilograms use the exact factor 0.45359237. Display changes and unchanged input events preserve canonical values. New automatically logged rows use one-set batches; existing multi-set batches remain intact. Row commands preserve surviving IDs and reject stale undo/corrections. Failed committed writes publish neither history nor new totals; failed recovery writes retain input. **Try again** retries the captured transaction and its destination, keeps failures visible while storage is unavailable, and cannot duplicate sets. New intentional input supersedes an older failed action; suspension preserves a pending action before flushing recovery. Unreadable files remain untouched and fail visibly. The MVP has one main-actor writer.

Approved planning and architecture documents remain unchanged. New implementation notes describe this revision without replacing them. Saved routines and previous-workout reuse are available offline. Physical-device signing, VoiceOver and keyboard ergonomics still require device testing. Native simulator checks require full Xcode and a compatible installed iOS runtime.
