# Senda

A native iPhone training notebook. Browse a week, open a day, and enter individual sets. The app saves locally; no account, network service, backend or cloud dependency.

## Run

1. Open **Senda.xcodeproj** in Xcode 16.4 or later with an iOS 17+ simulator.
2. Run **Senda Sample** for a populated sample week. Sample changes stay in memory.
3. Run **Senda** for a real journal with automatic local persistence and recovery. Physical-device builds need your development team and signing configuration.

The project has no third-party dependencies or generation step.

## App sections

A minimal bottom dock has **Log**, **Trends**, **Learn**, and **Profile**. Labels stay on one line and scale through xxxLarge; at accessibility sizes, press and hold a destination for the system’s large label-and-symbol preview. Page text and workout values keep their full Dynamic Type range. Selection has a filled symbol, small checkmark, emphasized label and selected accessibility trait. Valid set changes save automatically while editing. Switching sections closes the editor and keeps partial input recoverable; failed saves retain the current section. Log returns to the selected day and exercise.

**Workout plans** live beneath each exercise’s heading. Set a working-set target and rep range for that workout; targets stay separate from recorded sets. New exercise entries reuse the plan from the nearest earlier workout containing that exercise. Reusing a chosen workout also copies its plans only for newly added exercises. Past workouts keep their own plan, and removing the latest plan prevents an older target being silently revived.

**Set type** has its own control and defaults to Working set. Choose Working set, Warm-up or Drop set; choices save immediately. Older Regular annotations display as Working without rewriting stored history. A Drop set is one entry with a starting weight/reps stage and numbered drops. **Add drop** creates the next editable stage; every valid update saves automatically. The entry counts once in day/week/Trends totals while history retains every stage. Warm-ups and Drop sets do not count toward the Working target, and Drop workouts receive manual load-review guidance. Repeating a Drop entry copies every stage with fresh identities and clears effort; delete/Undo acts on the complete entry, and individual stages can be removed. Choosing another type splits stages into separate sets while retaining their values. Optional **Reps left** lives in row actions and appears inline when set. [UX audit](docs/design/2026-11-09-ui-ux-audit.md).

**Next workout** feedback uses journal-recorded working sets and saved plan snapshots. It can suggest repeating a load, building reps within the range, or reviewing a small load increase after two consecutive comparable workouts meet the top rep target with at least 2 reps left on every working set. This is a conservative, visible app rule; it does not choose an increase or change a weight. Missing effort/type, incomplete/extra sets, mixed loads, changed plans or below-range reps produce specific review messages. [Plan and guidance details](docs/implementation/2026-11-09-training-plans.md).

**Trends** leads with a selectable Strength progress chart, the chosen exercise’s latest exact set and its existing weight/reps comparison. View history opens that exercise’s recorded days. Weighted sets plot top-set load; body-weight-only windows plot best reps, and mixed added-weight windows label the added load. A single day is one point; empty windows have no chart. The remaining overview shows recorded activity over 8 or 12 calendar weeks: unique training days, recorded sets, exercises trained and weekly training-day bars. History and Records sit beside the title, adapting to narrow screens and Larger Text. Expanded All-time records appear above the period controls and are independent of that period. This week compares only the same elapsed weekdays last week. Top-set comparison rows show the latest two recorded days: rep changes at the same load, load changes at the same reps, matched sets or neutral side-by-side changes. Milestones mark heavier weight, or more reps at the same weight, against all earlier history; first observations and ties are not new records. Comparisons and Milestones appear before weekly activity. Each comparison keeps its dated source sets, using a single line where readable and stacking with Larger Text. Rows and all-time records open read-only exercise history without moving the current workout. Regenerate the focused visual fixtures with `swift run senda-preview --trends-only /absolute/output/directory`. [Trends details](docs/implementation/2026-11-09-trends-overview.md).

**Profile** has three direct destinations: **Name**, **Weight units**, and **Backup & restore**. The name is optional and saved on this device. Cancel and Done remain visible while editing; the keyboard’s Done action uses the same save and validation. Weight units opens only the lb/kg choices, with changes saved immediately. All logged exercise PRs and the Big 3 breakdown live in Trends → Records. It does not create an account or automatically sync. Email is no longer requested or shown; previously saved profile data remains compatible. The total adds the heaviest logged bench, deadlift and squat sets; reps break weight ties. A total appears only when all three lifts have records. This is a sum of observed sets, not an estimated one-rep max or competition result. Tap a PR to inspect its original set in read-only history. Corrections, deletion and Undo update progress from the journal. Default units affect progress and new days, preserving existing day units and canonical weights.

Profile details use a separate versioned atomic local file. An unreadable profile stays untouched and does not prevent logging. There is no account authentication or synchronization.

**Exercise history** is available from Trends or the chart button beside the current exercise. Choose an exercise and an 8- or 12-calendar-week chart window (default 12, including the current partial week through today). Recorded days lists all saved dates independently of that chart window, including older and deliberately future-dated entries. Daily points show actual top recorded sets; weighted exercises use load then reps, bodyweight-only periods use best reps, and mixed bodyweight/loaded periods show added load. Weekly training counts include inactive weeks. Dates use the saved training-day keys, so changing timezone does not move linked history. Newest-first days open the exact saved sets inside Exercise history, preserving the current workout; **Return to workout** closes into the same selected day/exercise. **Edit this workout** explicitly opens the saved day for corrections. A persistent return control restores the original workout/exercise or week while retaining the historical edits. Drafts and unfinished correction text are excluded from observations, while corrections/deletion/Undo and restore update them from performed history. [Progress details](docs/implementation/2026-11-09-exercise-progress.md).

**Backup & restore** opens directly from Profile. **Save full backup** exports a Senda JSON file containing the complete notebook, workout plans, set type/effort annotations, custom exercises, recorded identities, dates, exercise order, units, unfinished edits and local profile details. **Export recorded sets (CSV)** produces a readable spreadsheet with exact lb/kg weights and recorded set IDs; CSV cannot restore the notebook. Save files using the system picker, for example in Files or iCloud Drive. Senda does not encrypt exported files.

**Choose backup to restore** validates a Senda JSON file (up to 50 MiB), shows its contents and asks for confirmation before replacing the current notebook and local details. It does not merge. A pre-restore copy is retained on this device and can be exported with **Save pre-restore copy**. Interrupted or failed file replacements recover both original files before normal use. If the notebook cannot open, recovery also offers an unchanged original-file export and validated restore. When original files are damaged, the protected raw-file copy is exportable for recovery and is clearly distinguished from a restorable full backup. [Implementation and verification](docs/implementation/2026-11-09-backup-profile.md).

**Learn** has searchable offline setup, movement and form cues for all 20 presets, with front/back muscle maps separating primary movers, assisting muscles and stabilizers. Fifteen variations include inspected, licensed start/end illustrations; tap a position to enlarge it. Library rows include visual thumbnails and named primary muscles. Search supports exercise names, muscle groups and equipment, with Clear search and an actionable empty state. Opening a guide starts at its title; Back keeps the query and restores the selected row. Guide headings follow the notebook scale, and the enlarged illustration header adapts to Larger Text. Broad exercise names specify the variation covered. Custom exercises remain searchable and clearly show when a guide has not been added. Coaching references and illustration credits open only on tap. [Form sources](docs/implementation/2026-11-08-form-sources.md), [anatomy notes](docs/implementation/2026-11-09-learn-anatomy.md), [artwork credits and coverage](docs/implementation/2026-11-09-learn-artwork.md).

## Notebook flow

- **Week → Day → Exercise.** A Monday–Sunday list shows each day's trained muscle groups and set count. Categories appear once, using only performed sets; opening the day shows the individual exercises and sets. Days without logged sets show **+ Start workout**. Meaningful unfinished input changes this to **Continue workout** and appears separately from performed totals; untouched blank rows do not add a badge. Tap the row to open that day's workout, keeping any unfinished entries. The month appears on the left; **Today** and the grouped previous/next arrows sit on the right. Today returns to the current week without creating a workout. Weeks crossing months show both month names without years. Swipe left for the next week or right for the previous week; vertical scrolling and the arrow controls remain available. In the day view, arrows beside the date move to the previous or next calendar day; **‹ Week** returns to that day's week. Historical and future days show their context and **Go to today**, which preserves drafts on their original dates. Each day retains its own exercise tabs, selection and sets. Changing days finishes the current edit, preserving incomplete input without counting it.
- The current exercise appears once in a compact selector. Its menu switches exercises, opens **All exercises**, and hides a selected exercise while retaining its work. Add, history and units remain beside the selector. The day list includes hidden exercises with saved values or partial input and can restore their visibility. It shows the actual logical set count; a grouped Drop entry counts once.
- Use **+** for recent recorded exercises and the library. Search, muscle-group and equipment filters apply together; the compact **Filters** disclosure shows active restrictions, and **Clear filters** keeps the search text. Flat rows show **Added** when already in the day. Normal selection adds one exercise; **Select several** keeps an ordered selection for one atomic **Add N exercises** action. Failed selection remains visible and retryable; changing intent or Cancel prevents an old failed add from appearing later. **Create exercise** accepts a name, muscle group and equipment. Existing unclassified custom exercises remain searchable under Full body / Other.
- Each set has one weight value and reps. The compact **lb/kg menu beside the exercise name** changes the day's display unit without rounding untouched canonical values. The plan and collapsed performance references share one compact band. **Previous workout · top set** and **PR** remain distinct when expanded. The previous-workout reference uses that day's top set; **Last set** beside prefill uses the immediately preceding recorded set. PR ranks performed weight first, then reps. Tap a reference to inspect its source day read-only.
- A newly added exercise starts with a blank row. **New set** reuses an entirely empty final row, or adds another blank row, and focuses Weight or bodyweight Reps. A blank row can show **Use last values**, sourced from the nearest actual earlier set. Tapping it saves a new editable set with those exact values immediately. No values are copied without an explicit user action.
- Tap a value to edit. **Reps →** moves from Weight to Reps within the row. On a complete final row, **Next set** opens a blank working set using the current input method. Incomplete input or a save error keeps that continuation unavailable. Every valid update saves immediately, including dial and step controls. **Done** closes the editor. A weighted set needs a weight and 1–999 reps; bodyweight needs reps alone. Explicit zero weight is allowed.
- A complete new row counts immediately while editing. Partial input is saved without adding an invalid observation to history. If an existing set temporarily has an incomplete value, its last valid values and identity stay in history. Simple field guidance explains what needs a value; **Restore saved values** restores the last valid set. Valid corrections update that same set automatically. Explicit deletion remains separate.
- There is no recording step, recorded/not-recorded row label or completion checkbox. A save failure retains current input and offers Retry. Retry preserves set identity and saves once. An abruptly interrupted edit reopens with its saved input.
- The low numeric editor opens weight on a finger-draggable full-range dial, with Reps, Done and minus/plus. Tap its large value to type; the ruler steps aside for the keyboard. The keyboard-dismiss button returns to the dial without changing the value. Reps open directly for typing. The editor always labels Weight with the current unit or Reps. During editing, headings compact and Last/PR become an expandable reference. At accessibility text sizes, row values stack and grow, and typing plus large steppers replace the visual ruler.
- **Repeat last set** copies the immediately preceding complete entry and counts it immediately. For a Drop entry it repeats every stage under a fresh group ID, preserving exact values and clearing effort. **Undo** removes that copy; Undo after deleting an entry restores all original rows and identities. New edits or navigation clear the older undo action.
- Each entry has a three-dot menu for optional effort and deletion. Drop stages have their own effort/removal menus. Swipe left to reveal a red X; swipe farther and release to delete the whole entry. Vertical scrolling and cancelled gestures never delete. Failed saves remain retryable. **Undo** restores the entry in its original position.
- Hold an exercise tab to **Hide tab**. This retains its rows and history; every recorded or meaningfully unfinished hidden exercise remains reachable in **All**. The week's totals still reflect actual performed sets.
- **Use a previous workout** on an empty day or in the exercise chooser lists earlier recorded training days. It appends missing exercises in source order with blank rows, preserving destination sets and drafts. It never copies performed records, weights or reps. Repeating the action is harmless.

## Tests

```sh
bash scripts/test.sh
swift run senda-sample
# Full Xcode and an installed iOS runtime:
bash scripts/test-ios.sh
SENDA_SIMULATOR_NAME='iPhone 13 mini' bash scripts/test-ios.sh
```

Unit tests use Swift Testing and work with standalone Mac Command Line Tools. Restricted environments can pass writable cache locations and `--disable-sandbox`. The iPhone script creates and removes only its own temporary simulator; `SENDA_SIMULATOR_ID` can use an existing simulator. Results are in ignored `TestResults/`, or `SENDA_TEST_RESULTS`. Both Xcode schemes include the interaction tests for ⌘U.

The GitHub **iPhone validation** workflow runs unit tests and interactions on iPhone 16 and iPhone 13 mini using Xcode 16.4. Debug UI tests use UUID-isolated journals. Result bundles are retained for seven days. The workflow does not deploy a service.

Coverage includes ordered batch/set identities, duplicate-action protection, automatic row boundaries, incomplete recovery, bodyweight requirements, day isolation and summaries, Last/PR projections, date/DST arithmetic, exact lb/kg conversion and unchanged-input echoes, repeat/delete undo, invalid workspace data, custom exercise classification, legacy editor recovery, migrations and failed atomic writes. iPhone flows cover navigation, entry, units, rapid typing, finger dial, recovery, source-day editing, grouped/custom picking, undo and large text.

## Architecture and data

| Module | Responsibility |
| --- | --- |
| `SendaDomain` | Journal commands and receipts, individual set operations, validated day/workspace values, classification and conversion |
| `SendaPersistence` | Main-actor snapshot repository; memory and versioned atomic JSON adapters |
| `SendaLogger` | Weekly application model, candidate transactions, projections and legacy recovery review; original logger retained for compatibility |
| `SendaNotebook` | Native week/day/picker views, set rows, banners, numeric input and recovered-entry UI |
| `App` | Real/sample composition, lifecycle finishing and local-file opening |

The real file stays at Application Support `Senda/journal-v1.json`. Format 7 stores the journal, custom library and weekly workspace atomically, including explicit Drop groups and grouped Undo. An enabled marker protects against a missing workspace. Formats 1–6 load without rewriting; the next accepted mutation writes the current format. Full backups write version 4 and read versions 1–4. CSV includes group and stage columns.

Performed IDs, original dates and consumed action receipts are preserved. Day membership is explicit, so time-zone changes do not relocate saved sets. Undated legacy unfinished sessions move to the migration day's workspace without being counted. Removed-tab sessions remain recoverable. A legacy open group editor or pending recorded correction gets a one-time Done/Cancel review before weekly migration. Input in that review is also recoverable. Old unfinished batches are never automatically recorded during migration.

Weights are integer hundredths of a pound. Kilograms use the exact factor 0.45359237. Display changes and unchanged input events preserve canonical values. New automatically logged rows use one-set batches; existing multi-set batches remain intact. Row commands preserve surviving IDs and reject stale undo/corrections. Failed committed writes publish neither history nor new totals; failed recovery writes retain input. **Try again** retries the captured transaction and its destination, keeps failures visible while storage is unavailable, and cannot duplicate sets. New intentional input supersedes an older failed action; suspension preserves a pending action before flushing recovery. Unreadable files remain untouched and fail visibly. The MVP has one main-actor writer.

Approved planning and architecture documents remain unchanged. New implementation notes describe this revision without replacing them. There is no sync, backend, named-routine library or global undo stack; copying an earlier workout’s exercise structure is supported locally. Physical-device signing, VoiceOver and keyboard ergonomics still require device testing. Native simulator checks require full Xcode and a compatible installed iOS runtime.
