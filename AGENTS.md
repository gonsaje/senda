# Senda project guidance

## UI design direction

- Preserve Senda's ivory (#F7F3EB), terracotta (#A94E32), charcoal (#302720), and established Georgia notebook headings.
- Do not add decorative vertical accent bars, left-border callouts, or left stripes on rows, cards, banners, or empty states. This is an explicit user preference. Preserve meaningful chart axes, ruler ticks and scroll-edge indicators.
- Show selection with a checkmark and text emphasis; retain accessibility selected traits. Do not rely on color alone.
- Use typography, alignment, spacing and ordinary separators to establish hierarchy. Use native app controls where they fit the task. Prefer flat lists to repeated card containers.
- Give empty or incomplete states a clear label and next action. Do not show oversized placeholder values or empty charts that resemble measured progress.
- Keep visual treatments purposeful. Avoid redundant eyebrow headings, decorative icons, stock motivational copy and excessive explanation in the main task flow. Put necessary details beside the action they explain.
- Show set type in its own column with a prominent button. New sets default to Working set; Regular is a stored compatibility alias only. Type choices save immediately. Drop sets are grouped entries with editable weight/reps stages. Adapt narrow and Larger Text layouts without shrinking numeric values or tap targets. Keep ordinary narrow-screen weight and reps side by side; stack them for Larger Text when necessary. Keep optional effort in row actions, with an inline summary when provided.
- Keep essential targets at least 44 points, support Larger Text without shrinking key values, and verify compact screens. Save valid set changes automatically on user updates. Do not show recorded/not-recorded row statuses or require Done to save. Preserve partial input, last valid values and save-failure recovery.
- Review real rendered screens before changing styles. Assess hierarchy, alignment, density, action placement, state clarity and accessibility. A stylistic pattern alone does not prove AI authorship.
