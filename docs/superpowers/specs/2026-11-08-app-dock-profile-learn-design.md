# Senda dock, profile and learning

Build on the existing notebook with a quiet bottom dock: Log, Learn, Profile. Log retains the selected day and exercise when switching sections. Finishing an edit before leaving Log records valid sets and retains incomplete input outside progress; a failed write keeps the current section and editing context. Keep the ivory, terracotta, olive and charcoal language, serif titles and legible tabular numbers. The dock has three large targets and a hairline, without floating cards.

Profile contains editable on-device name and optional email under Account details, a functional default weight-unit setting, all exercise PRs and a prominent Big 3 section. The user confirmed the Big 3 adds the heaviest logged bench, deadlift and squat sets; reps break weight ties using the existing PR rule. Show the actual reps and source dates, a labeled three-part breakdown and no total until all three lifts have records. Do not call it a one-rep max or competition total. All progress derives from committed journal entries, updates after corrections/deletion/undo, includes custom exercises, and can open the original set in Log.

Account details remain local, consistent with the existing local-first scope. Store them through a separate small domain/repository/model boundary so account metadata cannot rewrite or corrupt the training journal. An unreadable profile leaves its bytes intact and does not block logging. Settings use the existing preferred unit for progress and new days; changing that preference does not round or convert performed sets or change an existing day's display unit.

Learn provides searchable, grouped form guides for all 20 preset exercises. Each guide has concise setup, movement and technique cues available offline, with an explicit link to its primary source. Do not fabricate guides for custom movements; identify their guide availability clearly. Use original summaries, no copied photos or video assets. The source link opens only when selected.

Approach chosen by implementer: a custom SwiftUI safe-area dock keeps the existing notebook and input dock, while platform TabView would add a different visual treatment and platform-specific layout. Use a simple proportional bar with labeled values for the Big 3; a historical line chart would answer a different question. Add a standalone local profile file rather than extending the already approved journal format. The original planning and architecture reports remain unchanged. No authentication, cloud, sync, backend, hosting or TestFlight release.
